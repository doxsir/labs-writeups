# TIL: GraphQL может вернуть 200 OK и всё равно облажаться

Дата: 2026-09-20

Пытался закрепить репозитории в профиле GitHub через GraphQL мутацию:

```graphql
mutation { pinItem(input:{itemId:"..."}) { clientMutationId } }
```

Ответ: HTTP **200 OK**. Проверка `curl -w "%{http_code}"` — зелёная, двигаюсь дальше.
Спустя пару часов смотрю на профиль — пинов нет. Перечитываю тело ответа:

```json
{"errors":[{"path":["mutation","pinItem"],
  "extensions":{"code":"undefinedField"},
  "message":"Field 'pinItem' doesn't exist on type 'Mutation'"}]}
```

Мутации не существует в текущей схеме, но HTTP-код всё равно 200. Это норма
GraphQL: транспортный успех ≠ успех операции. **Ошибки живут в теле, в поле `errors`.**

Правильная проверка:

```bash
curl -s ... | python -c "import json,sys; d=json.load(sys.stdin); \
  assert 'errors' not in d, d.get('errors'); print('ok')"
```

Плюс мораль шире: когда автоматизируешь что-то через API, проверяй **семантический**
успех (нужное поле в ответе, объект реально создан), а не транспортный код. HTTP-коды
в GraphQL отвечают на вопрос «дошёл ли запрос», а не «сработал ли».
