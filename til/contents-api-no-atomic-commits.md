# TIL: Contents API не умеет атомарные многофайловые коммиты

Дата: 2026-09-20

Пушил каркас cvedigest-ui (9 файлов) через GitHub Contents API — и получил
**9 отдельных коммитов** вместо одного. Каждый `PUT /contents/{path}` — это
самостоятельный коммит с собственным sha. Атомарного способа «запушить пачку
файлов разом» у Contents API нет.

Варианты, если нужен один коммит на много файлов:

1. **Git Data API** (деревья + коммит + ref) — можно собрать настоящий коммит
   с деревом файлов. Много ручной работы, но атомарно.
2. **Обычный git push** — если файлы локально, проще всего.
3. Жить с пачкой мелких коммитов. Для истории разработки это даже честнее:
   «deps: react», «entry html», «advisory list» — как реальные промежуточные
   шаги.

Кстати про sha: Contents API требует sha существующего файла для UPDATE,
но не для создания. И `GET /contents/{path}` на несуществующий файл вернёт
404, что надо ловить как «ок, создаём», а не как ошибку.

Второй подвох того же вечера: GraphQL возвращает **HTTP 200** даже на ошибки —
детали в [graphql-200-with-errors](./graphql-200-with-errors.md). GitHub API
умеет удивлять с двух сторон одновременно.
