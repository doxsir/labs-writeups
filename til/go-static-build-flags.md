# TIL: CGO_ENABLED=0 и -ldflags "-s -w" — почему бинарник Go уменьшился вдвое

Дата: 2026-09-26

Собирал релиз gokev и заметил: обычный `go build` даёт бинарник ~8 МБ, а с

```bash
CGO_ENABLED=0 go build -ldflags="-s -w" -o gokev .
```

получилось ~4.5 МБ. Что происходит:

- `-s` — убрать symbol table (символы для отладчика)
- `-w` — убрать DWARF-отладочную информацию
- `CGO_ENABLED=0` — выключить cgo. Это главное: с включённым cgo линкер тянет
  libc (динамическую), бинарник становится «не совсем статическим» и зависит
  от системной glibc на целевой машине. С `CGO_ENABLED=0` net/http использует
  чистую Go-реализацию DNS — и бинарник запускается на любом линуксе, хоть на
  alpine без libc.

Минус: нет символов → стек-трейсы без имён (обфусцированные). Лечится сборкой
отдельного debug-бинарника или сохранением символов через `-ldflags="-keep_unreachable"`...
проще: если нужен дебаг — собери вторую версию без `-s -w`, они не мешают друг другу.

Для security-CLI вывод: всегда `CGO_ENABLED=0`. Статический бинарник, который
просто работает на любой машине — это половина ценности Go-инструмента.
Вторую половину даёт `go vet` в CI, но это уже другая заметка.
